# Median - Architecture and decisions

This is the specification, updated after phase 9 so that it describes the code as built. Every entry of docs/DECISIONS.md is reflected here; the decision log keeps the reasons and dates.

## 1. Purpose and pipeline
Collect -> Check -> Review -> Classify -> Search.
- Collect: crawler add-ons (server-side) and manual upload (web page, API, CLI import) put files into staging through ONE ingest service.
- Check: exact duplicates are dropped automatically, including duplicates of discarded files. Visually similar files are flagged, never dropped automatically.
- Review: the user archives or discards each pending file. Discarded files keep their hashes so they keep counting as duplicates. Decisions can be undone.
- Classify: each archived file sits in exactly one folder (folders nest) and has any number of tags. Tags supplied by crawlers are added by default; the user can add or remove any tag.
- Search: by tags, folder, dates, type, source, status, text; saved searches.
- Operate: password, settings, scheduled maintenance (backup, integrity, tool updates, housekeeping, trash purge), startup recovery.

## 2. Stack (change only with a DECISIONS.md entry)
- Python 3.12+, managed with uv (image pins ghcr.io/astral-sh/uv:0.11.32). pyproject.toml and uv.lock are committed; Docker installs with uv sync --frozen. The project itself is installed (build backend uv_build) so its entry points exist.
- FastAPI on Uvicorn. Pydantic v2, pydantic-settings. python-multipart (streaming upload parser). httpx (tests and the direct add-on).
- PostgreSQL 18 (Docker image postgres:18). The app image has postgresql-client-18 from apt.postgresql.org (pg_dump/pg_restore; the build fails unless they are version 18) and rsync.
- SQLAlchemy 2.x async ORM with the psycopg 3 driver. Alembic for migrations. DATABASE_URL and TEST_DATABASE_URL are libpq URLs; app.config converts them for SQLAlchemy.
- Procrastinate (PostgreSQL-backed job queue) for all background work, wrapped in app/jobs/.
- UI: server-rendered Jinja2 templates, htmx 2.0.11 vendored at app/web/static/vendor/, small vanilla JS modules in app/web/static/js/, plain CSS (app/web/static/app.css). No SPA framework, no Node build step.
- Media: Pillow, ImageHash (pHash), numpy (>= 2, numpy.bitwise_count); ffmpeg and ffprobe in the image.
- Crawlers: yt-dlp[default] and gallery-dl in a separate venv at DATA_DIR/tools/venv, run as subprocesses, never imported into the app. Deno 2.9.7 (denoland/deno:bin-2.9.7) is copied into the image for yt-dlp.
- croniter for schedules. Session cookies are signed with hmac from the standard library.
- Tests: pytest, pytest-asyncio, httpx. Lint and format: ruff. The dev dependency group is installed in the image too (make test and make lint run there).

## 3. Runtime
Docker Compose services sharing one image (venv at /opt/venv, PYTHONPATH=/app, non-root user median):
- db: postgres:18, volume pgdata; an init script creates the test database.
- web: uvicorn app.main:app on port 8000 (host port WEB_PORT).
- worker: python -m app.worker --concurrency=4. It runs startup recovery (section 15), installs or upgrades the crawler tools (skipped with MEDIAN_SKIP_TOOLS=1; failures are logged and the worker starts anyway), then execs the procrastinate worker.
- Volumes: pgdata and media-data (DATA_DIR). docker-compose.override.yml (development) bind-mounts the code, enables reload and mounts ./imports read-only at /imports. Deployments use docker-compose.yml alone.
- make up starts db, runs make migrate (Alembic upgrade head, then the Procrastinate schema only if it is missing; idempotent), then starts web and worker.

Configuration (environment, see .env.example): DATABASE_URL, TEST_DATABASE_URL, DATA_DIR (/data), APP_TIMEZONE (Asia/Seoul), APP_PASSWORD (empty = no login), SECRET_KEY (empty = generated once in DATA_DIR/secrets/session_key), IMAGE_PHASH_THRESHOLD (6), VIDEO_FRAME_THRESHOLD (8), TRASH_RETENTION_DAYS (7), REVIEW_ORDER (oldest), BACKUP_RETENTION (14), TOOLS_UPDATE_SCHEDULE (0 5 * * 1), WEB_PORT (8000), POSTGRES_*. The thresholds, retention, time zone, review order, backup retention and tool schedule can be overridden on /settings (section 15).

## 5. Storage layout (under DATA_DIR)
- staging/<batch_id>/<file>: ingested files awaiting review (batch_id = upload batch, CLI import run or crawl run). Uploads stream into staging/<batch_id>/.upload-<uuid>.part and are renamed in place. Empty batch directories are left in place.
- archive/<sha[0:2]>/<sha[2:4]>/<sha>.<ext>: archived originals (sha = hex SHA-256).
- thumbs/<sha[0:2]>/<sha>.webp: thumbnails, max edge 320 px, kept for archived AND discarded files. Video thumbnails come from 10 percent of the duration (1 s if unknown), else the first frame.
- trash/<sha>.<ext>: originals of discarded files, purged after TRASH_RETENTION_DAYS (allows undo).
- work/<job_run_id>/: crawler working directories, removed when a run ends.
- addon_state/<source_id>/: persistent per-source state for add-ons (also HOME of their subprocesses).
- secrets/: session_key; secrets/<source_id>/<field>: uploaded secret files of sources (directory 0700, files 0600).
- addons/*.py: single-file add-ons. tools/venv/, tools/uv-cache/, tools/versions.json: crawler tools. logs/jobs/<job_run_id>.log: job logs. backups/db-<UTC timestamp>.dump: database dumps.
Rules: moves are atomic (temp file in the destination directory, fsync, os.replace). Files are deleted or moved only after the database transaction that records the change commits (run_after_commit; a move failing after commit is logged, and the integrity check finds it). A file is never overwritten: undo uses a suffixed name if the old staging name was reused. ext is lowercase and comes from the detected type, falling back to the original extension.

## 6. Data model (migrations 0001-0007)
All ids are bigint identity; all times timestamptz in UTC.
- files: id; sha256 bytea(32) unique not null; size_bytes; mime; ext; media_kind enum(image, video, audio, other); width, height, duration_ms (nullable); status enum(processing, pending_review, archived, discarded, error); error_message; staging_path (relative, set while processing, pending_review or error); has_thumb bool; phash bigint (images; 64-bit pHash as signed int64, two's complement); original_filename; title; description; folder_id fk folders (archived files only); collected_at; reviewed_at; archived_at; discarded_at; metadata jsonb (probe_error, perceptual_error, default_folder_id of the crawl source). Indexes on status, folder_id, collected_at, archived_at, media_kind, (status, archived_at DESC, id), (status, collected_at DESC, id), and duration_ms for videos.
- video_frame_hashes: file_id fk, frame_index smallint 0-4, phash bigint; primary key (file_id, frame_index).
- file_sources: id; file_id fk; source_key text ('upload' or an add-on key); remote_id text null; url text null; source_id fk crawl_sources null (on delete set null); job_run_id fk job_runs null (on delete set null); fetched_at; raw_metadata jsonb. Unique (source_key, remote_id) where remote_id is not null.
- ingest_events: id; at; outcome enum(new, duplicate_exact, skipped_known_remote, forced_reingest, error); file_id null; source_key; remote_id; url; job_run_id fk null (on delete set null); batch_id (indexed; the staging batch, used for upload progress); detail text.
- similar_pairs: file_a_id < file_b_id (check); method enum(image_phash, video_frames); distance smallint; dismissed bool default false; created_at; primary key (file_a_id, file_b_id, method); index on file_b_id.
- folders: id; parent_id fk folders null (null = top level); name; created_at. Names unique among siblings (unique index on (coalesce(parent_id, 0), lower(name))). A top-level folder "Inbox" is created by migration and cannot be deleted, renamed or moved (it may have subfolders).
- tags: id; name unique (already normalized); created_at.
- file_tags: file_id, tag_id, origin enum(crawler, user), removed bool default false, created_at; primary key (file_id, tag_id); index (tag_id, file_id) where removed = false.
- review_actions: id; file_id fk (on delete cascade); action enum(archive, discard, replace); previous_status; previous_folder_id fk (on delete set null); at; undone bool; group_id uuid (the two rows of a replace); detail jsonb (previous staging_path, timestamps and the file_tags rows the action created, re-activated or removed, for exact undo).
- crawl_sources: id; name; addon_key; config jsonb (validated model dump, secret fields left out); schedule text null (cron, read in APP_TIMEZONE); enabled; default_folder_id null; default_tags text[]; max_runtime_minutes (default 120); last_run_at (when the last run was queued); created_at.
- job_runs: id; source_id null; kind enum(crawl, rehash, integrity, backup, update_tools, purge_trash, recompute_similar, housekeeping); status enum(queued, running, succeeded, failed, cancelled); queued_at; started_at; finished_at; cancel_requested; queue_job_id (the Procrastinate job); stats jsonb; log_path; error. Partial unique indexes: one queued or running run per source, and per kind for every kind but crawl. Index (kind, status).
- saved_searches: id; name unique (as typed); query text (must parse); created_at.
- app_settings: key text primary key; value jsonb; updated_at. schedule_state: name primary key; last_fired_at (maintenance schedules).

## 7. File lifecycle
The ingest service is the only way files enter: ingest(path, origin, batch_id=None, original_filename=None, copy=False) where origin (IngestOrigin) has source_key, remote_id, url, source_id, job_run_id, tags, tag_origin (crawler by default; user for the upload page, API and CLI), title, description, metadata, default_folder_id, force. It moves (or, for the CLI import, copies) the file into staging/<batch_id>/ and defers the job process_ingest. That job:
1. If remote_id is set and (source_key, remote_id) exists in file_sources and not force: event skipped_known_remote, delete the incoming file, stop.
2. Compute SHA-256 by streaming (1 MiB chunks), outside any transaction.
3. Claim the content with INSERT ... ON CONFLICT (sha256) DO NOTHING (concurrent copies wait for each other). If the sha exists: if force and the existing file is discarded, restore it to pending_review with the new copy as its staging file, clear discarded_at and reviewed_at and delete the old trash copy after commit (event forced_reingest). Otherwise (any status, processing and error included) event duplicate_exact, add a file_sources row if this source is new (with remote_id: (source_key, remote_id) not recorded yet; without: no row with the same file, source_key and url), merge tags (crawler tags never touch an existing row, removed or not; user tags re-activate a removed row as origin user), delete the incoming file, stop.
4. Otherwise the new files row (status processing) gets its sources and tags at once; then probe type and dimensions (Pillow first frame; else ffprobe, ignoring image pipes and attached pictures; else the extension, with metadata.probe_error when an image/video/audio extension did not decode), create the thumbnail, compute perceptual hashes (section 8; a hashing failure only sets metadata.perceptual_error), set status pending_review, event new.
5. On any exception: status error with error_message in a separate transaction; the file stays in staging; the review page's Failed tab (and POST /api/files/<id>/retry) re-runs the media work.
Review decisions (app/review/service.py; lists of files, rows locked in id order, per-file results, all moves after commit): archive(file_ids, folder_id = Inbox by default, add_tags as user tags, remove_tags_per_file) moves staging -> archive, sets folder_id, status archived, reviewed_at, archived_at and clears staging_path. discard(file) moves the original to trash/, sets status discarded, reviewed_at, discarded_at and clears folder_id, staging_path and archived_at; hashes, thumbnail, sources and tags stay. An archived file can be discarded from the library (same rules). replace(new, old) archives the new file into the old one's folder with the union of active tags and discards the old one. Compare decisions are all or nothing: keep_left, keep_right, keep_both (also dismisses the pair), replace. Every decision checks that the original is where its status says. undo(action_ids) reverts an action only if it is the newest non-undone action of its file and the file is still in the state the action left (a replace is undone as a pair); it restores the staging path, folder (Inbox if the folder is gone), timestamps and tags, and is refused once the trash original is purged. purge_trash deletes trash files whose discarded_at is older than TRASH_RETENTION_DAYS; it changes no row.

## 8. Duplicate rules
- Exact: SHA-256 equality against files in every status. Automatic.
- Known remote: (source_key, remote_id). Automatic, checked before hashing.
- Perceptual (never automatic, shown in review): images use ImageHash phash with hash_size 8 on the EXIF-transposed RGB image (first frame of animations); similar when Hamming distance <= IMAGE_PHASH_THRESHOLD. Videos hash 5 frames at 10, 30, 50, 70 and 90 percent of the duration (ffmpeg seek before input, one PNG frame); clips under 1 s hash one frame from the middle; frames ffmpeg cannot produce are left out; videos without a known duration get no hashes. Two videos are compared when abs(d1 - d2) <= max(1000 ms, 3 percent of the longer duration) and they match when min(3, common frames) frame pairs are <= VIDEO_FRAME_THRESHOLD; the stored distance is the low median of the compared frame distances. Audio and other files have no perceptual hash.
- New files are compared against all hashed files in any status, under a transaction-level advisory lock (hashing happens before it). Ingest only inserts pairs. rehash (recompute hashes from the originals, any status but processing) and recompute-similar (pairs from stored hashes with the current thresholds) keep the dismissed flag of a pair that still matches and delete pairs that no longer match. Dismissed pairs stay hidden; there is no undismiss.
- Implementation: brute force over a numpy uint64 array (numpy.bitwise_count) behind a SimilarityIndex interface, so a BK-tree can replace it later.
- Review badges count undismissed pairs: "similar to archived or pending (n)" and "similar to discarded (n)" (dashed red); with n = 1 the badge links to the other file.

## 9. Tags
Normalization: Unicode NFKC, trim, lowercase, collapse internal whitespace to one underscore, trim underscores, max 100 characters (cut, then trailing underscores trimmed). Namespace: the text before the first ":" is normalized like the value; if it then matches [a-z0-9_]+ the tag is "ns:value" (dropped when the value is empty), otherwise the whole string is a plain tag with the colon kept (for example "작가:홍길동"). Empty results are dropped. Non-Latin text is kept as is.
Origins: tags from add-ons are inserted with origin crawler. When the user removes a tag the row stays with removed = true, so recrawls and duplicates never re-add it. User-added tags have origin user; re-adding a removed tag sets removed = false and origin = user; restoring a removed tag keeps its origin.
Tag management: rename (merges into an existing tag after confirmation: one row per file, active if either was, origin user over crawler, earlier created_at), delete (force needed while active rows exist), list with active usage counts (files in any status), autocomplete (typed prefix normalized but a trailing separator kept; order by usage, then name).

## 10. Folders
One folder per archived file (only archived files have one). Names: NFC, whitespace collapsed, trimmed, 1-100 characters, no "/"; sibling clashes are case-insensitive. Folders can be created, renamed, moved (cycles rejected) and deleted. Deleting a non-empty folder needs move_contents_to_parent: files go to the parent (the Inbox for a top-level folder), subfolders go up a level, and a subfolder whose name clashes there is merged recursively. Display paths as "A / B / C"; resolve_path("A/B") matches each segment case-insensitively. Subtree queries use recursive CTEs. Counts (direct and with subfolders) count archived files. "Recent folders" are those with the newest archived_at.

## 11. Crawler add-ons
See docs/ADDONS.md for the author's view. Add-ons are Python classes registered through the entry-point group media_archive.addons (built-ins: demo, ytdlp, gallerydl, direct in pyproject.toml) or as single files DATA_DIR/addons/*.py with a module-level ADDON. Discovery runs once per process (web at startup, worker when it imports its tasks); broken add-ons and duplicate keys (first one wins) are listed on /sources. Each add-on has key ([a-z0-9_]{1,50}, "upload" reserved), name, version, description, a Pydantic ConfigModel and async run(ctx, config). Source forms are generated from the config's JSON schema; SecretFile fields are uploaded files kept under DATA_DIR/secrets, never in the database.
The CrawlContext gives: work_dir (empty, per run), state_dir (persistent, per source), secrets_dir, log (job log), source_id, job_run_id, emitted, is_known(remote_id), known_remote_ids(), emit(CrawledItem: path inside work_dir, remote_id, url, title, description, tags, metadata, filename), is_cancelled(), sleep(seconds), run_subprocess(args, timeout, cwd, env) (argument list, own process group, environment limited to PATH, LANG, HOME = state_dir, proxy and CA variables and env; output streamed to the job log; the group is killed on timeout or cancellation; last 50 lines returned). emit() hands the file to the ingest service with the run's source_id and job_run_id, the item's tags plus the source's default tags (crawler), and the source's default folder (preselected by the archive panel).
Runs: Run now or the schedule inserts a queued job_runs row (one active run per source, enforced by the database) and defers run_crawl (queue crawl). The runner moves it to running and ends it as succeeded, failed or cancelled; cancel is polled every second (the add-on gets 5 s to return, then its task is cancelled); exceeding max_runtime_minutes fails the run; work_dir is always removed. Stats: emitted is stored; new, duplicate_exact, skipped_known_remote, errors and pending are computed from ingest_events. The schedule_crawls task runs every minute: a source is due when croniter's next fire time after last_run_at (or created_at) has passed; a due source with an active run stays due (coalescing); manual runs work for disabled sources.
Built-in tool add-ons run yt-dlp and gallery-dl with their config files ignored, URLs after "--", and extra_args checked against denylists (app/crawl/safety.py) that also catch abbreviations, "=value" forms and short option clusters. ytdlp rebuilds its download archive from the database before each run and treats exit 101 (max_items) as success; gallerydl emits files whose sidecar exists and whose size was stable for 2 s; both emit while the tool runs and fail only when they emitted nothing.

## 12. Search
Filters (SearchFilter): folder (with or without subfolders), tags_all, tags_any, tags_none (resolved to ids; an unknown must-have tag matches nothing and gives a warning), date ranges on collected_at and archived_at as whole local days in APP_TIMEZONE, media_kind list, source_key list, status (pending_review, archived, discarded; default archived; error is not searchable), text phrases (case-insensitive substring of title, original_filename or description). Sorts: archived (default newest first), collected, size, each ascending or descending, and random (md5 of seed and id; the seed is in the URL). Keyset pagination with an opaque cursor tied to sort and seed, plus the total count.
Query syntax (parsed into the same filters; format_query writes the canonical form): bare tag = must have; +tag = must have (needed when the tag looks like a key); -tag = must not have; ~tag = any of; folder:"A/B" (includes subfolders); folder=:"A/B" (exact folder); collected:2026-01-01..2026-03-31, archived:..2026-05-01 and single days (open ranges allowed; folder and each date key at most once); type:image|video|audio|other, source:<key>, status:pending|archived|discarded (repeats are alternatives); "quoted words" = text search (\" and \\ escape). Keys are case-insensitive; errors carry the character position.
The /search page is server-rendered from q; the filter panel and the query box stay in sync through GET /api/search/parse; autocomplete through /api/search/suggest; saved searches through /api/saved-searches.

## 13. UI
Pages: / (dashboard: counts per status, disk usage per storage area and live free space), /upload, /review, /library (folder tree and grid), /files/<id>, /search, /tags, /sources, /jobs and /jobs/<id>, /settings, /login. One base layout with navigation and a search box. Media is streamed by /media/<id>/original (HTTP Range, 206; inline only for image, video and audio, otherwise a download; always with X-Content-Type-Options: nosniff and a sandboxing Content-Security-Policy) and /media/<id>/thumb. Each page lists its keyboard shortcuts behind the ? key; shortcuts are ignored while typing. Layouts work at phone width (wide tables scroll inside their own box).
Review: single, grid (G) and compare views; Pending and Failed tabs; filters (media kind, source, batch, similar). Keys: J/K or arrow keys move, A archive (opens the archive panel: folder tree with search, recent folders, inline subfolder, crawler tag chips, user tags with autocomplete, keep-tags toggle; Enter confirms, Esc cancels), D discard, S skip, C compare with similar files (then 1 keep left, 2 keep right, B keep both, R replace, C next similar, Esc back), X select, Shift+A and Shift+D apply to the selection, U undo the last decision, Enter opens the focused tile. Decisions are optimistic: a rejected one puts the file back with the server's message.
Library and search share one grid component with multi-select and bulk move (M), add tag (T), remove tag and discard.

## 14. Conventions
- Type hints everywhere; ruff clean.
- Services receive an AsyncSession; one transaction per request or job (ingest uses several short ones, see section 7). Jobs and the CLI open their own engine with NullPool.
- Times stored in UTC and displayed in APP_TIMEZONE.
- Logs go to stdout; job logs also go to logs/jobs/.
- Subprocesses take argument lists, never a shell. Database credentials reach pg_dump/pg_restore through PG* environment variables, never arguments.
- Test media is generated in fixtures (Pillow images; ffmpeg lavfi testsrc2/mandelbrot videos). No large binary fixtures.
- Tests never use the network. Real-network tests are marked network and skipped by default; timing tests are marked slow.

## 15. Operations
- Authentication: with APP_PASSWORD set, every route but /healthz, /login and /static/ needs the signed session cookie median_session (issue time + HMAC-SHA256 over it and the password hash, keyed with SECRET_KEY; HttpOnly, SameSite=Lax, Secure under https, 30 days; changing the password ends all sessions). Pages redirect to /login?next=..., the API and htmx get 401. Failed logins are slowed down per client IP (min(2^(n-1), 30) s, one attempt at a time, in memory). With or without a password, POST/PUT/PATCH/DELETE need an Origin (or Referer) whose host:port is the request's Host (403 otherwise). Without a password every page shows a "No password set" banner.
- Settings (/settings, app_settings): database values override the environment defaults; saving the default deletes the row; invalid stored values are ignored. A process cache serves code without a session; the web process refreshes it after each save and jobs reload it at their start. After a threshold change the page offers recompute-similar.
- Maintenance jobs (backup, integrity, update_tools, housekeeping, purge_trash, rehash, recompute_similar) all record a job_runs row with log and stats (one active run per kind). The schedule_maintenance task (every minute, APP_TIMEZONE) queues purge_trash 03:30, backup 04:00, housekeeping 04:30 daily, integrity Sundays 05:00 and update_tools on TOOLS_UPDATE_SCHEDULE; the first check only records the time; missed fire times coalesce. /settings has Run now for each.
- Backup: pg_dump --format=custom to backups/.db-<ts>.dump.part, checked with pg_restore --list, renamed to db-<ts>.dump; the newest BACKUP_RETENTION dumps are kept. Restore (python -m app.cli restore, make restore FILE=...) checks the dump first, then recreates the public schema, runs pg_restore --single-transaction and applies the migrations. make backup-files DEST=... copies archive/ and thumbs/ with rsync (no --delete).
- Integrity: missing archive/staging/trash originals, orphan archive and staging files (staging older than an hour and not referenced by a waiting job), leftover work directories, missing thumbnails, and with verify_hashes hash mismatches. Fixes (thumbnails, orphan staging files ingested as a new upload batch, work directories) are buttons on the run page and re-check each entry; nothing else is changed automatically.
- Tool updates: update_tools upgrades yt-dlp[default] and gallery-dl in the tool venv (uv pip, else the venv's pip) and records the versions before and after.
- Housekeeping: deletes finished job runs older than 90 days with their logs, orphan logs and finished queue jobs older than 90 days (ingest_events stay), re-queues files stuck in processing for over an hour, measures disk usage per storage area.
- Startup recovery (python -m app.worker, single worker assumed): running job runs become failed "interrupted", Procrastinate jobs in doing are failed (freeing source locks), files stuck in processing for over an hour get a retry job.

## 16. Verification
- make lint, make test (pytest in the web container against the test database, which is reset and migrated from scratch once per session).
- scripts/smoke.sh: the acceptance checks of phases 0-8 against a running stack (SMOKE_LOCAL=1 for a native stack).
- make e2e (scripts/e2e.py): starts its own Compose projects median-e2e-a and median-e2e-b (fresh volumes, APP_PASSWORD set, ports 18000 and 18001), drives the whole pipeline through the HTTP API (login, demo crawl, review with undo, recrawl, exact/resized/forced uploads, removed crawler tags, search, integrity, backup and restore into the second stack, 1,000-file CLI import with latency limits of 500 ms), prints PASS or FAIL per step and removes its stacks. E2E_LOCAL=1 runs the app natively against a given PostgreSQL server.
- CI (.github/workflows/ci.yml) on every push: builds the image, make up, make migrate twice, smoke.sh, make lint, make test; a second job runs make e2e twice; a third runs install.sh twice (fresh install with a password, then an update that backs up first and keeps .env).
- install.sh (repository root, POSIX sh): one-step install and update with Docker Compose. It checks Docker, clones or fast-forwards the code, writes .env from .env.example on the first run only (random SECRET_KEY and database password unless a median_pgdata volume exists, login password, host time zone, free port, COMPOSE_FILE=docker-compose.yml), backs up a running install, builds, starts db, migrates, starts web and worker and waits for /healthz. --configure-only is tested by tests/test_install_script.py.
- docs/MANUAL_CHECKLIST.md: the browser checks a person runs (keyboard review, compare, archive panel, library moves, search sync, video seeking, login, phone width).
